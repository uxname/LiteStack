# LiteStack

## Проблема и цель

LiteStack — уже существующий и активно используемый полностековый шаблон
(backend liteend-go + frontend litefront, координация сверху).

Цели — все четыре, ранжирование пока открыто (см. «Открытые вопросы»):

1. Быстрый старт нового продукта: auth, CI, деплой, доки уже собраны.
2. Единый стандарт всех проектов: один стек, одни приёмы, лёгкое переключение.
3. Сохранение накопленных лучших практик между проектами.
4. Витрина уровня инженерии для коллег, клиентов, сообщества.

Сверка с типовыми провалами шаблонов-стартеров показала: незакрытых болей
нет — шаблон живой, владелец сам следит за свежестью. Улучшения ищем
точечно, а не «просто сделать лучше».

## Пользователи и сценарии

- Автор проекта (ты) — использует активно, сам поддерживает и обновляет.

## Что входит

- Периодический аудит документации по всем трём репозиториям
  (мета-репо, backend, frontend): расхождения доков с реальностью
  собираются списком и правятся.

## Потом

- Автоматический смоук полного цикла первого запуска из чистого клона —
  станет нужным, когда старты станут частыми или появятся другие
  пользователи.

## Что НЕ входит

- Синхронизация производных проектов с апстримом: производный проект —
  snapshot fork и живёт своей жизнью (решение уже закреплено в
  OPERATING-MODE.md).

## Ограничения и риски

- Документ ведётся на русском языке — осознанное исключение из правила
  репозитория English-only: это рабочий инструмент владельца.
- В проекте принципиально нет CI — решения не должны требовать его
  появления.

## Решения и отклонённое

- PRD на русском, а не английском: скорость мышления владельца важнее
  единообразия репо для этого одного файла.
- Свежесть зависимостей — вручную, силами владельца: старты редки,
  автоматика (боты, календарь) не окупается.
- Автосмоук первого запуска отклонён в пользу ручной проверки по
  надобности.
- Дрейф доков ловим периодическим аудитом, а не автопроверкой команд и
  ссылок из доков: список от аудита дешевле и надёжнее скрипта.
